## 2026-11-04 · 修复：无操作时页面自己「回到顶部」

**现象**：不碰页面，画廊会自己跳到「回到顶部」那张卡的位置。

**原因**：这张卡的演示是自驱动的，每轮循环结束会调 `btn.click()` 让按钮执行回顶。程序化点击在部分 WebView 里会把焦点移到按钮上，浏览器为了显示获得焦点的元素会滚动所有祖先容器——包括画廊页面本身，于是整页被拉到这张卡。

**改动**
- 演示不再触发按钮点击，也不再调 `scrollTo`：回顶改为自己按比例递减 `scrollTop`（每帧 14% + 最小 2px），效果上是减速回顶，全程只作用于卡片内的滚动容器。
- 按钮点击（真实用户操作）仍走 `scrollTo({behavior:'smooth'})`，并把演示相位切到 `rest`，避免自动循环和用户操作打架。
- 六个内层滚动容器（视差、进度、堆叠、吸附、缩放、回顶）统一加 `overscroll-behavior:contain`，滚到边界不再把滚动链传给页面。

**教训**：演示里不要用 `element.click()` 代替「执行动作」。它不只是执行回调，还带着焦点与滚动的副作用，而这两样会跨出卡片作用到整页。

## 2026-11-04 · B3 滚动入库（37 → 42，新增第 9 个分类）

滚动类效果原先散落在「运动」里，只有一条「视差滚动」。这批把它独立成类，并补 5 条。

| 新增 | 演示的关键点 | 参数 | 驱动 |
|---|---|---|---|

| 粘性堆叠 | 四张卡依次停在顶部叠成牌堆 | 叠放间距 | 纯 CSS sticky |
| 横向吸附 | 横滑结束对齐整屏，圆点跟随 | 卡间距、圆角 | CSS snap + JS 自动切换 |
| 滚动缩放 | 起始 1.6 倍局部，滚到底退回 1.0 全景 | 缩放幅度 | JS 写 CSS 变量 |

**结构调整**：`CATEGORIES` 新增 `scroll`（8 → 9 类），「视差滚动」由 `motion` 迁入 `scroll`。迁动理由是同类横向对比——视差本质是滚动驱动的层间速度差，放在「运动」里会被误认成 hover 类微交互。

**一处计划外的替换**：计划里的「滚动视差文字」没有单独收。它与「视差滚动」是同一机制（不同层不同速率），按去重规则应记作 `variants`。空出的名额换成「滚动缩放」——位移速度差 vs 尺寸变化，边界清楚，产品里也更常见。

**实现取舍**
- 三条需要跟随滚动的（进度、缩放、回顶）都在 `scroll` 回调里只写 CSS 变量，不在回调里改 `style.width/transform`，避免同步布局。
- 横向吸附的当前页判定用「卡片中心与容器中心的距离」而不是 `scrollLeft / clientWidth`，因为卡间有 gap，除法会偏移。
- 粘性堆叠完全没用 JS，靠 `position:sticky` + 递增的 `top`；这类效果能纯 CSS 就别加监听。

**验证**：42 条字段完整、id 唯一、49 个 keyframes 全唯一（本批零新增关键帧，全部由 JS 驱动）、CSS 括号平衡、stage 类名与样式一一对应。仍只有 3 条历史告警（`--tl-max` / `--mg-strength` / `--cu-dur` 由 JS 读取，属预期）。

## 2026-11-04 · 页面自身的动效层（视觉打磨）

**目标**：页面外壳不能只是"静态陈列 24 个会动的卡片"，自身的节奏也要立住。

**动的东西**
- 背景：三团径向光缓慢漂移（26s，`alternate`），替代原来静止的固定渐变。仅此一处持续动画，避免抢卡片注意力。
- 首屏编排：顶栏下滑 8px 淡入 → 分类逐条左移入场（26ms 间隔）→ 卡片按行错峰上升（32ms 间隔，最多 9 档）→ 底部投喂区延后 120ms 进入。
- 卡片：鼠标位置驱动的柔光（`--mx/--my` + radial-gradient，rAF 节流）、悬停抬升 4px、点阵背景随悬停位移 7px、"调参 ↗"右移。
- 分类：悬停右移 2px，选中点弹入。
- 弹窗：遮罩淡入 + 面板 0.46s 减速入场，右侧内容与参数滑杆分 5 档错峰；关闭改为 170ms 淡出后再 `hidden`（原来瞬间消失）。
- 细节：顶栏滚动后加重阴影；切换主题时 480ms 颜色过渡；数量变化时数字轻弹。

**约束**
- 所有页面动画统一用 `--e-out: cubic-bezier(.22,1,.36,1)`，卡片悬停 420ms、入场 600ms，节奏一致。
- 新动画统一 `ui-` 前缀，避免与 24 个效果里已有的 `spin` / `fade-up` / `rise` 撞名（`spin` 已重命名为 `ui-mark-spin`）。
- 入场动画用 `animation-fill-mode: backwards`（不是 `forwards`），结束后自动归还 `transform`，否则 `:hover` 抬升会失效——这是个容易踩的坑。
- 「暂停动效」现在同时冻结背景光场；`prefers-reduced-motion` 下所有页面动画关闭、悬停位移取消。

## 2026-11-04 · 修复：卡片完全不动

**现象**：用户反馈"看不到动态效果"。

**根因**：`fx.css` 从未被写入页面。`mountInto()` 只把 `fx.stage` 塞进 `.stage`，但没有任何地方把各效果的 CSS 注入 `<head>`——所有卡片只有裸 HTML，没有定位、没有 `@keyframes`，因此完全静止。

**修复**
- 新增 `injectStyles()`：启动时把 24 条 `css` 合并注入一个 `<style id="fx-styles">`，`render()` 之前调用（只注入一次）。
- 去掉"系统偏好 `prefers-reduced-motion` 时自动暂停"的逻辑。动效展示站的第一帧必须是动的；需要静止的场景由右上角「暂停动效」手动控制。

**新增校验**
- 每条效果 `stage` 里出现的类名，必须在该效果的 `css` 中有对应规则（本次 24 条全部命中，合并后 16.7KB / 165 条规则）。
- 预览服务 `GET /effects.js` 返回 200，磁盘与线上字节数一致（无缓存问题）。

**教训**：数据驱动渲染里，"数据里有 css 字段"不等于"样式已生效"。这类缺陷编译期查不出，必须有一条"类名 ↔ 规则"的机械校验兜底。
