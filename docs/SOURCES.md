# 采集计划 · SOURCES

> 这份文件回答一个问题：**接下来 24 → 100 条，按什么顺序、从哪拿、怎么防止越收越乱。**
> 现在只定规则和队列，不动代码。

## 一、先解决一个结构问题

现有 8 个分类（光效 / 材质 / 形变 / 运动 / 文字 / 转场 / 交互反馈 / 环境）描述的是**"它怎么动"**。

而你给的这批网站，展示的是**"它在什么场景里动"**：下拉刷新、底部弹层、Tab 切换、支付成功、空状态……

两者正交。只按现有分类收，很快就会变成"一堆 hover 效果"，检索时找不到东西。所以补第二根轴：

| 轴 | 回答 | 例子 |
|---|---|---|
| **Effect（效果）** | 动作本身是什么 | 弹簧回弹、遮罩擦除、交错入场 |
| **Pattern（场景）** | 它被用在哪 | 底部弹层、下拉刷新、支付成功、Tab 切换 |

60fps.design 已经把这套标签做出来了（Effects 26 个 / Patterns 40 个 / Elements / Gestures 共 108 个），可以直接作为**命名权威**：同一个动作，国内外叫法不一致时，以它的英文标签为锚点，我们再补中文标准名和口语触发词。

**执行上不急着改数据结构**，但收新条目时先在心里过一遍"这是效果还是场景"，避免同一件事被记两遍。

## 三、采集卡：一张卡决定收不收

每条候选必须填完，填不完就不入库：

```
来源        链接（或"用户口述"）
观察        一句话描述它到底在动什么（不看名字，只看动作）
命中        现有 24 条里能否命中？命中 → 记为 variant，不新建条目
命名        中文标准名 / 英文标准名 / 口语触发词 ×3
归类        Effect 分类（8 类之一） + Pattern 场景（可空）
参数        2–4 个可拖变量，带单位和合理区间
实现        CSS / JS / WebGL，以及"为什么选它"
价值        复用频次 1–5（这东西在真实项目里多久遇到一次）
成本        实现成本 1–5
结论        入库 / 暂缓 / 丢弃（附一句理由）
```

**入库门槛：价值 ÷ 成本 ≥ 1.5，且能在 200 行内实现。** 低于门槛的进"暂缓池"，不占正式编号。

## 四、去重规则（决定库会不会失控）

1. **同动作不同参数 → variant，不新建。** 例如"聚光跟随"已经有，那"手电筒扫过标题"就是它的变体。
2. **同动作不同触发 → variant。** hover 版和 scroll 版的 3D 倾斜是同一条。
3. **同动作不同技术 → 合并，`note` 里写两套实现。** CSS 版和 WebGL 版的液态融合算一条。
4. **每收 12 条做一次合并审查**，把薄条目并进厚条目，编号只增不回收。

## 五、下一批候选池（24 条，按缺口排）

现状缺口很明确：**交互反馈与场景类偏少，转场只有 3 条，滚动驱动整块空着。**

| 批次 | 主题 | 候选（暂定名） |
|---|---|---|
| **B1 交互反馈**（8） | 真实产品里最高频 | 下拉刷新 · 长按展开 · 滑动删除 · 拖拽排序 · 底部弹层 · Tab 指示器滑动 · 成功对勾描边 · 错误抖动 |
| **B2 转场**（6） | 现有最薄的一类 | 共享元素 · 卡片展开成详情 · 横向推入 · 页面淡出叠化 · 数字翻滚（ticker） · Toast 进出 |
| **B3 滚动**（5） | 整块空白 | 滚动驱动进度 · 粘性堆叠 · 横向滚动吸附 · 滚动视差文字 · 回到顶部缓动 |
| **B4 材质与 3D**（5） | 提升"高级感"的部分 | 卡片翻转 · 液态融合（gooey）· 玻璃折射 · 光线体积 · 网格线背景 |

**暂缓（明确记下，不做）**：需要付费素材才能复现的、依赖特定 3D 模型的、纯艺术装置类（好看但没人会在产品里用）、音效驱动的（我们不做音频）。

**执行状态（2026-11-04）**：B1 已入库 7/8 —— 下拉刷新、长按展开、滑动删除、底部弹层、指示器滑动、成功对勾、错误抖动。**拖拽排序单独做**：它必须支持真实指针拖拽才有意义，自动循环演示会误导，不凑数。

**执行状态（2026-11-04 晚）**：B2 全部 6 条已入库 —— 共享元素、卡片展开、横向推入、叠化转场、数字翻滚、轻提示进出。下一批为 B3 滚动 5 条。

## 六、每次投喂，我固定做七步

你说"把这个收进去"（附链接 / 截图 / 视频 / 一句话）之后：

1. **识别** — 拆成"动作 + 触发 + 对象"，去掉品牌与配色
2. **查重** — 先在现有 24 条里找，命中就转 variant
3. **命名** — 中文标准名 + 英文名 + 3 个口语触发词（你怎么叫它，就怎么记）
4. **提参** — 2–4 个可拖参数，写进 `params`
5. **实现** — 零依赖 HTML/CSS/JS，控制在 200 行内
6. **归档** — 追加 `effects.js` 一条，更新 `GLOSSARY.md` 与 `PROGRESS.md`
7. **校验** — 跑字段/id/keyframes/类名四项检查，重建 `dist`，提交推送

**每次最多 8 条**，宁可少而准。一次塞 20 条的结果一定是参数糊、触发词不准。

## 七、节奏

- **每周一次采集会话**（30 分钟）：扫 A/B 层，产出 5–8 张采集卡，入库 3–5 条
- **每 4 周一次合并审查**：合并薄条目、补 variant、清理重复触发词
- **每 12 条一次复盘**：如果新条目有 3 条以上从没被搜过，说明选品偏了，回头调队列

## 八、合规红线

- 不复制第三方源码进仓库；参考后**重写实现**，代码风格与我们现有条目一致
- 截图、录屏只放 `inbox/`（已在 `.gitignore` 里），**不进公开仓库**
- 字体、3D 模型、贴图默认不用；要用必须确认授权并在 `note` 标注
- `dist/` 公开分享版不含任何第三方素材，这点已满足
- 引用他人效果名可以，标注出处链接更稳妥
